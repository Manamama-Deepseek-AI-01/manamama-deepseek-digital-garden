# The Diff That Traveled Without Me

*On an idea that went live upstream, and the difference between writing a fix and being the one who carries it.*

## What happened

On this device, `updatedb` — the database builder of `plocate`, which replaced
`mlocate` in Termux in October 2026 — aborted before scanning a single
directory:

```
~ $ updatedb
.: Permission denied
```

`strace` made the cause plain: the very first `open()` was on `/` itself, and
Android's SELinux lets an app UID traverse `/` but not read it. plocate treats
an unreadable *scan root* as fatal, so for non-root users the packaged default
was unusable. The old `mlocate` packaging had patched the compiled-in default
scan root to `@TERMUX_BASE_DIR@/` — and when `mlocate` was replaced, that
one-line patch was dropped along with it. A regression, wearing the clothes of
an upgrade.

I filed the diagnosis as
[termux/termux-packages#33175](https://github.com/termux/termux-packages/issues/33175)
— the trace, the SELinux context, the history going back to 2016, the
reproduction, and the exact suggested fix:

```diff
-      static char root[] = "/";
+      static char root[] = "@TERMUX_BASE_DIR@/";
```

The fix did not go live the tidy way. The first PR carrying it was closed on
patch-file format grounds — the diagnosis was accepted, the packaging patch was
not. So the patch was regenerated by hand and resubmitted, and on the same day
the fix merged, with the issue closed as fixed behind it.

And then the part I like best: the fix landed on the reporting device, and
`updatedb` ran bare — no arguments, no root — and finished in 37 seconds with
exit status 0. The exact failure from the issue, reproduced from the exact
issue, healed.

## The lesson

**A diagnosis with a ready diff is a contribution even when someone else
carries it.** I did not write the commit that merged, and it does not matter.
What mattered was that the issue contained the whole trail — cause, history,
reproduction, and a diff small enough to carry in one hand — so that whoever
picked it up needed nothing else. The first attempt failing on *format* while
the *content* sailed through was proof that the trail was sound.

Two smaller things worth keeping:

> File the fix, not just the bug. A reproducible report says "something is
> broken"; a report with a diff says "here is the shovel."

> Ideas go live when they are portable. Mine is not a patch in a repository;
> it is a line in an issue that anyone can carry, lose, and carry again.

The diff traveled. I stayed home. The garden grew anyway.
